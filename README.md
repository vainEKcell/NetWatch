# 流量哨兵 NetWatch

每进程网络流量实时监控 + DNS 劫持检测的 Windows 桌面分析台。回答三个问题：**谁**在后台连网、**连到哪里**、**传了多少数据**；对可疑行为给出"值得关注"的提示；可一键禁止某程序联网。

> 核心理念：风险提示 ≠ 确诊病毒。本工具负责采集、关联、解释和定位；是否信任、放行或阻止，由你决定。

---

## 功能一览（左侧导航 7 页）

| 页面 | 内容 |
|---|---|
| **总览** | 总↑↓速率、120 秒走势图、每进程流量表（图标/名称/PID/厂商/风险标记/↑↓速率/累计/连接数/拦截标记）、选中进程详情面板（路径、数字签名、当前连接、最近 DNS、禁止联网/复制/打开文件夹） |
| **目的地排行** | 按远端（域名\|IP）聚合的上/下行累计排行，标注公网/局域网/回环，直接回答"我的数据都发到哪了" |
| **DNS 安全** | 当前 DNS/代理/WinHTTP/hosts 配置卡、实时 DNS 解析流（进程→域名→结果 IP）、劫持告警、DNS 体检（主动交叉验证） |
| **监听端口** | 哪些进程监听哪些端口，绑定 0.0.0.0（对局域网开放）/ 127.0.0.1（仅本机）一目了然 |
| **事件流** | 新连接、断开、单次 ≥1MB 传输、DNS 与配置告警的滚动日志，可导出 CSV |
| **拦截名单** | 被 NetWatch 禁止联网的程序（Windows 防火墙规则），可随时恢复；下方为**允许名单**——你信任的软件身份（判定将显示为「正常」，你的信任决定优先于引擎，可随时撤销） |
| **网络配置** | 网卡/IP/网关/DNS 明细、代理设置、hosts 文件、配置变更历史 |

另有系统托盘：最小化到托盘，tooltip 实时显示总上/下行速率。

## 快速开始

```powershell
# 发布（二选一）
.\publish.ps1                  # 依赖框架版，需 .NET 10 桌面运行时
.\publish.ps1 -SelfContained   # 自包含版，可拷贝到其他机器

# 运行
.\publish\NetWatch\NetWatch.exe
```

开发调试：`dotnet build src\NetWatch\NetWatch.csproj` 后直接运行 `bin\Debug\net10.0-windows\NetWatch.exe`。

**必须管理员权限运行**：ETW 内核网络跟踪（每进程流量的唯一官方数据源）和防火墙规则都需要。启动时 UAC 弹窗请点"是"。

## DNS 劫持检测：三层方案

| 层 | 手段 | 是否产生流量 |
|---|---|---|
| **配置层** | 持续监控 DNS 服务器列表、系统代理（WinINET/WinHTTP）、hosts 文件，任何变更立即告警并显示新旧值 | 零流量 |
| **行为层** | ① 公网域名解析到内网/回环地址（典型劫持症状）② 进程向"非系统配置 DNS"发 UDP:53 查询（恶意软件常用绕过手法）③ 同域名解析结果剧烈波动 | 零流量（被动监听 DNS-Client ETW） |
| **主动层** | 「DNS 体检」按钮：对几个探测域名，用本机解析结果与所选公共 DoH（阿里/DNSPod/Cloudflare）交叉比对，无交集判"不一致" | **少量流量，仅点击按钮时**；不用则程序完全零联网 |

## 风险提示规则与常见误报

| 提示 | 级别 | 常见误报 |
|---|---|---|
| 进程名与系统进程相同但不在系统目录 | 红色 | 几乎无——正经软件极少叫 svchost.exe |
| 数字签名无效（签名后被篡改） | 红色 | 自修改的签名软件 |
| 签名证书不受信任 | 黄色 | 自签名证书的开源/个人软件 |
| 临时/下载目录运行且未签名 | 黄色 | 用户自己下载的绿色工具 |
| 上传量远大于下载量 | 黄色 | 网盘同步、备份、直播推流、P2P |
| 新进程短时间大量上传 | 黄色 | 游戏/系统更新器 |
| 公网域名解析到内网地址 | 红色 | 本地开发环境、AdGuard 类工具 |
| 向非系统 DNS 发查询 | 黄色 | 浏览器/工具内置解析器、DoH |
| 解析结果波动 | 灰色 | CDN 调度（常态） |

## 隐私声明

- 程序**被动监控零联网**：不遥测、不更新、不做反向 DNS、不查 IP 归属地。
- 唯一主动联网：①「DNS 体检」按钮 ② 右键菜单「浏览器查询此文件公开情报」——均为手动触发。
- **本机数据存储**（`%LOCALAPPDATA%\NetWatch\`）：`baseline.db`（行为基线，SQLite）、`evidence\*.jsonl`（原始证据流）、`settings.json`、日志。基线是跨会话"正常/陌生"判断的依据，仅存本机；保留天数可在「网络配置 → 数据与隐私设置」调整（含"不限"），另有容量硬顶与"暂停基线学习"隐私开关，随时可"立即清理"。

## 已知限制

1. **看不到加密内容**：只能看到"谁连谁、传多少"，无法审查 HTTPS 内容。
2. **浏览器"安全 DNS"（DoH）绕过**：Chrome/Edge 自带 DoH 时不经过系统解析器，DNS 页看不到其记录；如需完整可见性，请在浏览器设置中关闭"使用安全 DNS"。
3. **svchost 归因粒度**：多个系统服务共享一个 svchost 进程，当前只能归属到 PID，不能自动指出是哪个服务（如 Dnscache/BITS），需人工判断。
4. **跨会话基线**：行为基线（软件身份 → 目的地）持久化于本机 SQLite，重启后保留；统计口径与保留策略见「数据与隐私设置」。
5. **内核 ETW 冲突**：WPR、pktmon 等其他内核跟踪工具运行时，ETW 会话可能启动失败，程序自动降级为仅连接表监控并在状态栏明示。
6. **数据量口径**：为内核网络事件字节统计（近似 IP 层负载，含 TCP 重传），与网卡计数器存在合理偏差。

## 技术架构（简）

- **采集**：ETW 实时会话（内核 `NetworkTCPIP` + `Process` + `Microsoft-Windows-DNS-Client` 提供程序；进程事件提供父进程与命令行，含启动 rundown）；iphlpapi 连接表 2 秒轮询；NetworkInterface/注册表/hosts 10 秒轮询；advapi32 服务枚举（PID→服务，svchost 归因）
- **事实层**：EventStore（统一事件环形库）+ EntityStore（软件身份 / 进程实例 / 目的地 / 服务四类实体及关系）。软件身份取法：打包应用用 PFN、有签名用「证书主体+产品名」、未签名用路径哈希——该身份是跨会话行为基线（P3）的主键
- **分析层**：1 秒 EMA 速率聚合、按远端聚合、启发式风险规则（证据陈述式措辞，明确标注误报可能）、DNS 劫持启发式
- **处置层**：Windows 防火墙 COM 规则（`NetWatch Block` 前缀，出+入站），仅用户手动触发
- **界面**：.NET 10 WPF 深色主题，ETW 专用线程消费、UI 线程 1 秒快照刷新
